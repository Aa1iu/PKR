## 一、当前信息流总览（正常路径）

```
用户上传文档
  → POST /api/kbs/{kb_id}/docs/upload → 保存文件 + 创建 Document 记录 (status=processing)
  → 后台任务 BackgroundTasks:
      ① parse_document_pages() → DocumentPage 表（阅读用，保留真实页码）
      ② parse_document() → chunk_text() → BGE-M3 Embedding → ChromaDB（RAG 用）
      ③ status → ready
  → 用户提问
  → POST /api/chat (SSE)
      → RAGService.search_chunks() → Embedding → ChromaDB 检索 → Jaccard 去重
      → LLMService.chat_stream_rag() → DeepSeek 流式
      → SSE 事件: source → token → done
  → 知识图谱
  → POST /api/kbs/{kb_id}/analyze → LLM 概念提取 → 去重 → 关系识别 → Concept/Relation 表
  → GET /api/kbs/{kb_id}/graph → 前端 D3 力导向图
```

**这条主链路基本通畅，但存在以下断裂点。**

## 二、🔴 致命问题（功能不可用）

### F1. 后端缺少 `/file` 端点 — PDF/DOCX 阅读直接 404
- **实测**：`GET /api/kbs/{id}/docs/{id}/file` → **HTTP 404**
- **文件**：`backend/app/routers/docs.py`（路由不存在）
- **影响**：前端 `DocReader.tsx:35` PDF `<iframe>` 空白、`DocxHtmlRenderer.tsx:30` mammoth 加载失败提示"请确认后端 /file 端点已就绪"
- **修复**：新增路由返回 `FileResponse(doc.file_path)`，按扩展名设 MIME type

### F2. `page-image` 端点返回 501 — PPTX 画廊不可用
- **实测**：`GET /api/kbs/{id}/docs/{id}/page-image?page=1` → **HTTP 501**
- **文件**：`backend/app/routers/docs.py:281-293`（TODO 占位）
- **影响**：`PptxGalleryRenderer.tsx` 图片永远加载失败
- **修复**：LibreOffice 转 PNG（或降级为返回源文件）

### F3. 文档上传后不自动触发图谱分析 — 图谱永远是空的
- **实测**：文档 status=ready，但 `GET /graph` → `nodes=0, edges=0`
- **根因**：
  - 后端上传流水线（`docs.py:_process_document_background`）**没有调用 analyze**
  - 前端**没有触发分析的按钮**（`POST /analyze` 端点前端从未调用）
- **影响**：图谱页永远显示"该知识库还没有图谱数据"或空图
- **修复**：上传成功后自动 `run_analysis`，或前端图谱页加"分析"按钮 + 进度轮询

### F4. FloatChat 浮动窗口永远走全局对话
- **文件**：`frontend/src/components/FloatChat.tsx:35` — `useChatStream()` 没传 kbId
- **影响**：用户在知识库页面打开浮动窗口提问，回答不会基于该知识库内容
- **修复**：FloatChat 引入 `useKBStore.currentKbId`

### F5. DocReader 刷新页面必然失败
- **文件**：`frontend/src/pages/DocReader.tsx:74-76`
- **根因**：kbId 从 `location.state` 获取，路由 `/wendang/:docId` 不含 kbId，刷新后 state 丢失
- **修复**：路由改为 `/wendang/:kbId/:docId`，或从 API 按 docId 反查

## 三、🟠 高优先级问题

### H1. 对话历史 100% 内存存储，服务重启全丢
- **文件**：`backend/app/routers/chat.py:39` `_chat_store` dict
- **影响**：`ChatMessage` ORM 表建了但从未写入（死表）；重启后端后对话全消失

### H2. SSE error 事件不可达 — LLM 错误被伪装成正常回答
- **文件**：`backend/app/services/llm_service.py:136-150` + `chat.py`
- **根因**：`_stream_api` 捕获所有异常后 `yield "[LLM 调用失败: ...]"` 作为 token 内容
- **影响**：前端永远收不到 `{"type":"error"}` 事件，API key 错误时用户看到的是普通回答文本

### H3. 图谱分析首次运行批内去重失效
- **文件**：`backend/app/services/graph_analyzer.py:148-178`
- **根因**：`existing_embs = []` 时 `if existing_embs:` 为假，跳过批内去重和向量累积
- **影响**：首次分析时 LLM 返回的重复概念全部入库，图谱重复节点多

### H4. 概念-文档关联是假数据
- **文件**：`backend/app/services/graph_analyzer.py:181-189`
- **根因**：每个概念无条件关联前 3 个文档（`doc_ids[:3]`）
- **影响**：图谱节点浮窗的"关联文档"列表不准确

### H5. 三个占位空壳端点
| 端点 | 现状 |
|---|---|
| `GET /kbs/{id}/export` | 返回空 `concepts/relations/documents`，DB 里明明有数据 |
| `POST /kbs/{id}/reindex` | 返回 `status=completed` 但什么都没做（误导前端） |
| `GET /kbs/{id}/concepts/{cid}/positions` | 永远返回 `positions=[]`，ConceptDocRef 表有数据没读 |

### H6. `get_doc_content` 忽略 page 参数
- **文件**：`backend/app/routers/docs.py:254-276`
- **根因**：接受 `page` 参数但始终返回全部页
- **影响**：契约语义不明确；前端 TXT 分页纯前端实现

### H7. 文档 status 枚举前后端不一致
| 位置 | 值 |
|---|---|
| 后端实际 | `processing` / `ready` / `error` |
| 前端类型 | `processing` / `ready` / `analyzed` / `error` / `failed` |
- **影响**：前端 `analyzed`/`failed` 分支永远不命中（KBDetail 显示 fallback）

### H8. requirements.txt 缺 `langchain-text-splitters`
- **文件**：`backend/requirements.txt`
- **影响**：新环境 `pip install -r` 后跑文档解析会 `ModuleNotFoundError`（当前环境碰巧装了）
