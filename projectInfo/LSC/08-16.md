## 【23:00】问题排查 — 图谱不生成 + PDF 解析失败

### 用户反馈
1. 已有知识库加 docx 后图谱不更新
2. 新库加 pdf/docx/pptx：pdf 解析失败，另两个解析成功但图谱没生成

### 根因排查（重要经验）

**核心根因：8000 端口后端未配置 DeepSeek API Key**
- 前端 vite 代理指向 8000，但该端口服务器无 Key（占位符 `your-api-key-here`）
- 所有图谱分析请求 401 → `run_analysis` 静默失败 → 图谱永远空白
- 分析状态是内存 dict，重启后 idle，无法追溯失败原因（掩盖了 401）

**附带发现**：
- 8000 端口是 Windows 孤儿 socket（进程已死但句柄残留，PID 无法杀，需重启电脑释放）
- 改用 8001 端口 + 设置 Key 后一切正常

### 修复
1. `vite.config.ts` 代理 8000 → **8001**
2. 算法库手动分析 → **13 节点 / 9 边**（算法复杂度、动态规划、贪心、A* 等）
3. AI Agent 库增量分析 → **17/17 → 22/21**（新 docx 概念已合并）

### PDF 解析失败结论
- `人工智能课本-重点.pdf`：解析仅 156 字符且全是换行符 → **扫描版 PDF（无文本层）**
- PyMuPDF 无 OCR 能力，无法提取扫描版文本 → 技术限制，非 bug
- 建议：此类文档转文字版或用有文本层的 PDF

## 【23:50】执行修改 — 分页 bug 修复 + PPT 图片展示（#4 完整实现）

### 分页 bug（重要）

**根因**：前端 `getDocumentContent` 默认参数 `page=1` 永远发 `?page=1` → 后端单页模式只返回 1 页。
**影响**：所有文档阅读只显示第 1 页（md/txt/pptx 全中招）。
**修复**：前端默认不传 page；后端 `page` 默认改 `None`（不传=全量，>0=单页）。

### PPT 图片展示（LibreOffice 已安装）

- 后端 `_ensure_ppt_images`：soffice PPTX→PDF（headless）→ PyMuPDF 渲染 PNG（120 DPI）→ `data/ppt_cache/{doc_id}/` 缓存
- `page-image` 端点：pptx 返回真实 PNG；非 pptx 保持降级返回源文件
- 前端 DocReader：pptx 分支切回 `PptxGalleryRenderer` 图片画廊
- 验证：首次转换 8 秒（17 页）→ 缓存秒开 → 超范围 404
